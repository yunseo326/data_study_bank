# 비료 추천 모델링 프레임워크

## 문제와 평가

각 행의 정답 비료는 하나지만 제출에서는 확률이 높은 비료 3개를 순서대로 냅니다.
정답이 첫 번째면 1점, 두 번째면 0.5점, 세 번째면 약 0.333점입니다. 따라서 단순
정답률뿐 아니라 클래스 확률의 순서가 중요합니다.

주지표는 seed 326의 Stratified 5-Fold OOF MAP@3입니다. Log loss와 fold 편차는
확률 품질과 검증 안정성을 확인하는 보조 지표로 기록합니다.

## 데이터에서 확인한 출발점

- 학습 750,000행, 테스트 250,000행, 예측 특성 8개, 타깃 7종입니다.
- 결측치와 test에만 존재하는 범주는 없습니다.
- 모든 수치형 특성도 고유값이 14~43개로 적어 범주형 처리 가능성이 있습니다.
- 단일 특성의 구분력은 약하지만 영양소·수분 조합에서 구분력이 커집니다.
- train/test 분포 차이는 작으며 ID 구간별 타깃 변화도 작습니다.

## 고정 실험 순서

| 실험 | 기준 | 한 가지 변경 | 목적 |
|---|---|---|---|
| E000 | 없음 | 클래스 빈도 상위 3개 고정 | 코드와 지표의 최저 기준선 |
| E001 | E000 | CatBoost 원본 특성 | 첫 학습 기준선 |
| E002 | E001 | 모델만 LightGBM | 모델 계열 비교 |
| E003 | E001 | 8개 특성을 모두 범주형 처리 | 낮은 cardinality 가설 |
| E004 | E001 | 선택한 쌍 상호작용 추가 | 변수 조합 가설 |
| E005 | E004 | fold-safe 타깃 인코딩 추가 | 상호작용을 클래스별 확률로 표현 |
| E006 | 완료 모델 | OOF 기반 확률 평균 | 서로 다른 오류의 보완 여부 확인 |

E005 이후에는 독립 실험 결과를 고정한 뒤 공개 상위권 해법을 비교합니다. 쌍, 삼중,
사중 조합과 원본 데이터 사용은 각각 별도 실험으로 분리합니다. 원본 데이터는 출처와
라이선스를 기록하기 전에는 사용하지 않습니다.

## 검증 규칙

1. 모든 실험은 같은 fold와 seed를 사용합니다.
2. 인코더와 타깃 통계는 각 학습 fold에서만 학습합니다.
3. ID는 기본 특성에서 제외하고 마지막 ID 20% 성능은 안정성 진단으로만 봅니다.
4. OOF 전체 MAP@3, fold별 MAP@3, log loss를 함께 기록합니다.
5. Public LB는 OOF 개선이 test에도 이어지는지 확인하는 보조 지표입니다.
6. 실패한 실험도 결과와 다음 가설을 기록합니다.

## 완료 기준

- 제출 행 수와 ID 순서가 test와 같습니다.
- 모든 행에 유효하고 서로 다른 비료 3개가 있습니다.
- OOF/test 확률은 유한하고 각 행의 합이 1에 가깝습니다.
- 원본 CSV 체크섬이 분석 전후 동일합니다.
- 중요한 결과가 실험표, 진행 로그, HTML 리포트에 함께 반영됩니다.
