# Bank 변수 사전과 해석 기준

공식 출처는 Kaggle 대회 설명과 UCI Bank Marketing 데이터 설명입니다.

- [Kaggle 대회 데이터 설명](https://www.kaggle.com/competitions/playground-series-s5e8/data)
- [UCI Bank Marketing](https://archive.ics.uci.edu/dataset/222/bank)
- [원 연구 논문](https://repositorio.biblioteca.iscte-iul.pt/bitstream/10071/9499/5/dss_v3.pdf)

Kaggle train/test는 원본 Bank Marketing 데이터를 학습한 딥러닝 모델이 생성한 합성 데이터입니다. 변수의 뜻은 원본을 따르지만 값의 조합과 분포가 원본과 완전히 같지는 않습니다.

| 변수 | 공식 의미 | 분석할 때 주의할 점 |
|---|---|---|
| `age` | 고객 나이 | 비선형 효과와 연령대별 표본 수를 함께 확인한다. 현실 적용에서는 공정성도 검토한다. |
| `job` | 직업 유형 | `unknown`은 하나의 직업이 아니라 직업 정보가 없는 상태로 본다. |
| `marital` | 결혼 상태 | 원본 정의에서 `divorced`는 이혼과 사별을 함께 포함한다. |
| `education` | 교육 수준 | 순서가 있어 보여도 효과가 선형이라고 가정하지 않는다. `unknown`을 유지한다. |
| `default` | 신용 채무불이행 여부 | 희소 범주라면 전체 정확도보다 양성률과 표본 수를 같이 본다. |
| `balance` | 연평균 잔액 | 단위는 유로다. 음수와 큰 양수 이상치가 있어 일반 로그 변환은 바로 적용할 수 없다. |
| `housing` | 주택담보대출 보유 여부 | 고객의 자산 수준과 동일한 의미로 해석하지 않는다. |
| `loan` | 개인대출 보유 여부 | `housing`과 다른 대출 정보다. |
| `contact` | 연락 통신 방식 | `unknown`은 연락 방식 정보가 없는 상태다. |
| `day` | 마지막 연락이 이뤄진 월중 일자 | 요일이나 경과일이 아니다. `month`와 함께 해석한다. |
| `month` | 마지막 연락 월 | 계절성뿐 아니라 은행의 캠페인 대상 선택이 섞여 있다. 연도 정보가 없어 정확한 시간순 검증 기준으로 쓰기 어렵다. |
| `duration` | 마지막 연락 통화시간 | 단위는 초다. 통화가 끝나야 알 수 있으므로 사전 고객 선별 모델에서는 결과 이후 정보에 가깝다. Kaggle 점수용 모델과 현실 모델을 분리한다. |
| `campaign` | 현 캠페인에서 해당 고객에게 연락한 횟수 | 마지막 연락을 포함한다. 예측 시점에 따라 값의 가용 범위가 달라진다. |
| `pdays` | 이전 캠페인의 마지막 연락 후 경과일 | `-1`은 이전에 연락한 적이 없다는 뜻이다. 상태 표시와 경과일을 분리할 수 있다. |
| `previous` | 현 캠페인 이전의 연락 횟수 | `pdays`, `poutcome`과 관련되지만 합성 데이터에서는 완전히 일치하지 않으므로 별도 변수를 유지한다. |
| `poutcome` | 이전 캠페인 결과 | `unknown`은 이전 결과 정보가 없음을 뜻한다. `pdays=-1`과 기계적으로 치환하지 않는다. |
| `y` | 정기예금 가입 여부 | Kaggle에서는 `y=1` 확률을 예측하고 ROC AUC로 평가한다. |

## 모델링 기준

1. Kaggle 점수 모델은 제공된 모든 피처를 쓸 수 있다.
2. 현실적인 사전 타기팅 모델은 `duration`을 제외해 별도로 평가한다.
3. 원본 데이터를 추가하는 실험에서도 검증셋은 Kaggle train의 홀드아웃으로 유지한다.
4. 원본 데이터는 각 학습 폴드에만 추가해 Kaggle 분포에 대한 OOF 개선 여부를 확인한다.
5. `unknown`과 `pdays=-1`은 0이나 최빈값으로 덮지 않고 정보 부재 상태로 유지한다.
