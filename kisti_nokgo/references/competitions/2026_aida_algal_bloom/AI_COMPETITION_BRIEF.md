# 2026 AIDA 녹조 7일 예측 대회 분석 브리프

작성 기준일: 2026-09-23  
대상 독자: 이 프로젝트에서 참가 여부와 분석 계획을 수립하는 AI  
문서 성격: 선택적 참고자료. 공식 규칙과 experiment artifact를 대체하지 않는다.

## 1. 결론

이 문제는 **기술적으로 해결 가능한 시계열 회귀 문제**다. 다만 “유용한 예측 모델을 만드는 것”과 공식 목표인 `R² 0.6`, `NSE 0.5`를 미래 연도에서 안정적으로 달성하는 것은 구분해야 한다. 공개된 국내 하류 낙동강 연구에서도 1일 예측보다 7·14일 예측이 크게 어려웠고, 두 장기 구간의 보고된 `R²` 범위가 `0.347~0.500`이었다. 따라서 목표치는 가능하지만 도전적이다.

현재 종합 판단은 다음과 같다.

| 항목 | 판단 | 근거 |
|---|---|---|
| 문제 해결 가능성 | 높음 | 다년간 수질·수문·기상 자료와 강한 자기상관·계절성이 있고, 유사 6~7일 예측 연구가 존재한다. |
| 목표 성능 달성 가능성 | 중간 | 데이터 수는 모델링에 충분하지만 작고, 관측 간격이 불규칙하며 급증 사건과 연도 이동이 크다. |
| 난이도 | 높음, 약 8/10 | 미래 누수 없는 융합, 불규칙 표본, 결측, 지점별 이질성, 극단값을 동시에 처리해야 한다. |
| 수상 가능성 | 조건부 중간 | 정량 성능 외에 창의성 20, 우수성 50, 효과성 30의 발표평가가 있다. 재현성·현업 활용·설명력이 강하면 모델 점수만 높은 팀보다 유리할 수 있다. |
| 권장 참가 판단 | 참가 가치 있음 | K-water 정책지정 문제로 현업 활용 서사가 명확하고, 이 프로젝트의 고정 검증·재현 파이프라인과 잘 맞는다. |

수상 가능성을 정확한 확률로 환산하지 않는다. 현재 사이트의 참가자 수는 전체 대회 기준이며 문제별 제출팀 수와 모델 성능 반영 비중이 공개되지 않았다. 실무적으로는 다음처럼 해석한다.

- 단순 모델과 단일 holdout만 제출: 낮음
- 시간 누수 없는 검증, 강한 baseline, 지점별 안정성, 재현 코드까지 완성: 중간
- 위 조건에 더해 불확실성·경보 의사결정·설비 배치 효과를 명확히 연결: 중간 이상

## 2. 공식 문제 정의

- 주과제: 5개 조류경보 지점에서 기준일로부터 약 7일 후 유해남조류 세포수 `cells/mL` 예측
- 기준일: 실제 조류 측정이 존재하는 날짜
- 정답일: `base_date + 7일`에 가장 가까운 실제 측정일. 차이가 ±3일 이내일 때만 채점
- 지점: 해평, 강정·고령, 칠서, 물금·매리, 대청호 회남
- 입력 도메인: 조류·수질, 댐 수문, ASOS 기상, 선택적 DataON 하천 수위
- 공식 시간 분할 설명: 학습은 2023년까지, 검증은 2024년, 비공개 평가는 2025년 이후
- 회귀 평가 설명: `log10(cells+1)`의 RMSE·MAE와 원 단위 R²·NSE
- 금지: 기준일 이후 관측값 사용, 실측 룩업테이블, 하드코딩, 재현 결과와 제출값의 유의한 불일치

공식 문제 페이지는 경보단계 분류를 부과제로 설명하고 회귀 70% + 분류 30%를 “예시”로 적는다. 그러나 제공 샘플 엑셀은 회귀 단일 과제이며 제출 열은 `pred_cells` 하나뿐이고 분류는 제외됐다고 적는다. **현재 가장 큰 규칙 리스크이므로 참가 전 Q&A로 확정해야 한다.**

## 3. 제공 샘플에서 확인한 데이터 구조

`sources/녹조.xlsx`는 공식 전체 번들의 일부를 설명하는 샘플이다. 샘플 자체를 formal experiment 데이터로 사용하지 않는다.

### 전체 번들 규모에 대한 샘플 안내문 정보

- 조류 측정 2,939행
- 댐 일자료 79,964행
- ASOS 일자료 32,208행
- 댐 운영 API 1,128행
- 채점 가능 조합 2,754행
- 분할 안내: 학습 2,310, 검증 256, 평가 124, 시즌 외 제외 64
- 대상 지점 5개

2,310개의 학습 조합은 트리 기반 표형 모델에는 사용할 수 있지만, 대형 딥러닝을 안정적으로 선택하기에는 작은 편이다. 같은 조류 측정값이 여러 base date의 feature 또는 target에 재사용될 수 있으므로 행 수를 독립 표본 수로 해석하지 않는다.

### 엑셀 샘플 점검 결과

- 조류 측정 87행 중 target 결측 3행
- 세포수 범위 `0~489,500`, 중앙값 `24,453`, 90백분위 약 `85,932`
- 4개 속 세포수 합계와 총 유해남조류 세포수는 비교 가능한 84행에서 모두 일치
- 샘플 채점 조합 75개 중 정확히 7일 간격은 51개뿐이며, 나머지 24개는 4~10일 간격
- 지점별 연속 관측의 절대 로그 변화 중앙값은 약 `0.17~0.53`이고, 최대 변화는 로그10 기준 `1.19~4.73`으로 급격한 변화가 존재
- 강정·고령 샘플 최대값은 약 48.95만 cells/mL로 급증 사건이 포함됨

이 분포에서는 원 단위 MSE만 최소화하면 극단값이 모델을 지배한다. 학습 target은 `log1p`가 기본이며, 제출은 역변환 후 음수를 0으로 제한하고 bias correction의 유효성을 검증한다.

## 4. 핵심 난점

### 4.1 진짜 7일 선행 예측

기준일 이후 실측 수질·수문·기상은 feature로 쓸 수 없다. 평가 시점에 존재하지 않는 `target_date`까지의 관측 기상이나 방류량을 합치면 높은 점수가 나와도 누수다. 미래 기상예보가 허용되고 평가 시점 스냅샷을 재현할 수 있을 때만 별도 데이터 원천으로 검토한다.

### 4.2 불규칙한 조류 관측

정답 간격이 4~10일로 달라진다. 단순 `shift(1)`은 7일 lag가 아니다. 모든 lag와 rolling feature는 날짜 차이로 정의하고, `days_since_last_sample`, 실제 정답 간격, 관측 공백 길이를 명시적으로 사용한다.

### 4.3 지점별 다른 생성 과정

낙동강 하천 4개 지점과 대청호 호소 1개 지점은 수리·생태 과정이 다르다. 물금·매리는 2020년부터 자료가 시작되어 짧다. 지점 ID를 넣는 것만으로 끝내지 말고 지점별 baseline, error, calibration을 별도로 확인한다.

### 4.4 급증과 연도 이동

녹조는 수온, 강우·유량 충격, 체류시간, 종 조성에 따라 비선형적으로 급증한다. 2024년 검증과 2025년 이후 평가의 기상·운영 조건이 학습 연도와 다를 수 있어 무작위 CV는 낙관적이다.

### 4.5 결측의 이중 의미

미채수와 분석중 값은 단순 누락이 아니라 홍수·경보·운영 상황과 연관될 수 있다. 결측 대체값과 함께 결측 플래그, 마지막 유효 관측 이후 경과일을 사용하되, 사후 확정된 결측 사유가 기준일 당시에 알 수 있었는지 확인한다.

## 5. 수상 전략

대회 문제해결 평가는 창의성 20점, 우수성 50점, 효과성 30점이다. 공식 Q&A는 모델 성능 비중이 문제별로 달라 정확히 공개하기 어렵고, 목적 연관성과 홍보효과를 위해 별도 산출물을 만들 필요는 없다고 답했다. 따라서 **성능을 기본 자격으로 만들고, 재현성과 운영 의사결정 연결로 우수성·효과성을 확보하는 전략**이 적절하다.

권장 차별화는 다음 순서다.

1. 누수 검사를 자동화한 날짜 기준 feature store
2. persistence·계절 baseline 대비 개선을 명시한 모델
3. 지점별·연도별·경보구간별 성능과 실패 사례 공개
4. 점예측과 함께 예측구간 또는 초과확률 제공
5. 7일 뒤 경계 이상 위험을 설비 선제 배치, 취수 심도, 고도정수 준비와 연결
6. 한 번에 재현되는 실행 코드, 데이터 manifest, 모델·feature 버전 기록

정확도만 조금 높이는 복잡한 딥러닝보다, 시계열 누수를 막고 설명 가능한 tree ensemble과 불확실성 추정을 결합한 완성도 높은 시스템이 이 데이터 규모와 심사 구조에 더 유리하다.

## 6. 권장 검증 설계

공식 비교용 Primary Validation은 공식 설명대로 고정한다.

- Train: 2023-12-31까지
- Validation: 2024-01-01부터 2024-12-31까지
- Group: `(station_id, base_date)`
- Feature cutoff: 모든 원천 데이터의 timestamp가 `base_date` 이하인지 자동 검사
- 평가: 공식 지표 후보 전부 계산. log RMSE, log MAE, 원 단위 R², NSE, 분류가 확정되면 Macro-F1

Primary Validation을 바꾸지 않고 다음 robustness를 추가한다.

- rolling-origin: 2021→2022, 2022→2023, 2023→2024
- leave-one-station-out는 공식 점수 대체가 아니라 공간 일반화 진단으로만 사용
- 고세포수 상위 10%, 급증 구간, 경보 경계 주변, 관측 공백 길이별 subgroup
- 지점별 metric과 global metric을 함께 기록
- 같은 target 측정일을 공유하는 표본이 train과 validation 양쪽에 들어가지 않는지 검사

## 7. 권장 모델링 순서

### 단계 A. 반드시 이겨야 하는 baseline

1. 마지막 세포수 유지 persistence
2. 지점×월 중앙값
3. persistence와 계절 중앙값의 가중 평균
4. 로그 target을 사용하는 선형 또는 regularized 모델

baseline이 없으면 복잡한 모델의 개선이 실제 예측력인지 판단할 수 없다.

### 단계 B. 주력 표형 모델

- HistGradientBoosting, Random Forest/Extra Trees, XGBoost·LightGBM·CatBoost 중 재현 가능한 2~3개
- target은 `log1p(cells)`
- 지점별 모델과 전 지점 통합 모델을 모두 비교
- seed와 feature set이 다른 소수 모델만 OOF 기반으로 blend

딥러닝은 tree ensemble을 명확히 이기고 연도별 안정성이 확인될 때만 후보로 올린다.

### 단계 C. 우선 feature

- 조류: 마지막 1~4회 log 세포수, 날짜 기준 7/14/28/56일 통계, 최근 증감률, 속별 비중, 우점 속 변화
- 수질: 수온, pH, DO, 탁도, 투명도, chlorophyll-a의 lag·이동 통계와 변화율
- 기상: 1/3/7/14/28일 평균 기온, 누적 강수, 무강수 일수, 일사·일조, 풍속, 습도, 수온 대리 누적열량
- 수문: 유입·방류량, 저수율, 수위, 강우의 lag·누적·변화율
- 기작 대리: `저수량 / 방류량` 형태의 체류시간 대리변수. 단위와 0 분모를 검증
- 정적: 지점, 수계, 하천/호소, ASOS 매핑, 관측 시작연도
- 시간: 월, day-of-year의 sin/cos, 녹조 계절 여부
- 결측: 변수별 missing flag, 마지막 유효 관측 이후 경과일

## 8. 참가 전 공식 확인 질문

다음 질문의 답이 없으면 제출 스키마와 Primary Metric을 확정하지 않는다.

1. 최종 제출은 `pred_cells`만인가, 경보단계 열도 필요한가?
2. 회귀 70% + 분류 30%가 실제 순위식인가? “예시”라면 최종 가중치와 정규화 방식은 무엇인가?
3. RMSE·MAE·R²·NSE를 모두 순위에 쓰는가? 지점별 계산 후 평균인지 전체 pooled 계산인지?
4. 음수 예측, 극단 예측의 clipping 규칙과 반올림 규칙은 무엇인가?
5. 비공개 평가의 정확한 기간과 2025·2026 자료 사용 범위는 무엇인가?
6. `target_date`가 제출 시 제공되는가, 참가자가 매칭해야 하는가?
7. 기준일 이후의 공개 기상예보를 입력으로 사용할 수 있는가? 허용된다면 과거 forecast archive의 기준은 무엇인가?
8. 조류 세포수 API의 단위는 실제로 cells/mL인가? 샘플 스케일과 공식 발령기준이 우선인지?
9. 경보단계 threshold는 상수원 하천·호소에 동일하게 적용되는가? 적용 매뉴얼 버전은 무엇인가?
10. DataON 수위 자료를 참가 코드에서 자동 취득해야 하는가, 원본 재배포 없이 파생 feature를 제출해도 되는가?

## 9. Go 또는 No-Go 기준

전체 번들을 받은 뒤 1차 EDA와 baseline을 짧게 실행해 다음을 확인한다.

- 2024 validation에서 persistence보다 log RMSE가 최소 10% 개선
- 주요 지점 모두에서 baseline보다 악화되지 않거나, 악화 원인이 설명 가능
- 원 단위 R²가 초기에 0.35 이상이고 feature 추가에 따라 일관되게 상승
- train/validation target 분포와 missingness 차이가 관리 가능한 수준
- 규칙 Q&A로 제출 열과 순위식이 확정

초기 R²가 0.2 미만이고 rolling-origin에서도 불안정하면 목표치 0.6 달성 가능성을 낮게 보고, 추가 데이터 확보 또는 참가 우선순위를 다시 판단한다. 반대로 단순 GBDT가 R² 0.45 이상이고 지점별 붕괴가 없으면 참가를 적극 진행할 가치가 높다.
